# G26 APP/FBL behavior audit — 2026-10-24

The target is a connected AUTOSAR Classic-like laboratory implementation without RTE, not formal AUTOSAR certification or support for every standardized service. This assessment follows the active APP/FBL source, the ZGW reference and the current RepoCM5 FCD source. Source behavior, host tests, Cortex-M linking, gateway integration and physical ECU behavior are separate evidence levels.

## FCD and ZGW contract

The G26 APP-image programming wire sequence is `10 02`, `31 01 00 01` with vector address and size, `34 00 44` with the same range, `36` blocks of at most 240 data bytes, and `37` with a big-endian IEEE CRC32. The FBL creates the 512-byte header, so the transferred image begins at `0x08020200`. FCD now has a G26-specific profile that coalesces HEX gaps as erased bytes, checks vector/range/CRC settings, verifies APP `G26A2` to resident `G26F2` handover, and requires routed target replies rather than a CAN TX-confirmation substitute.

The G26 FBL-image branch skips ZGW-specific RID `0200` and requests RID `0155` before erase/download. G26's resident FBL intentionally rejects `0155` while the updater interlock is off. ZGW source maps G26 response ID `0x709`, request ID `0x710`, route `0x55`, response EA `0xF0`, and gateway flow-control EA `0x41`; FCD handles routed `7F SID 78` until the final response. Host tests cover the request and identity sequence, but no ZGW firmware build or connected FCD/ZGW/G26 transaction has been completed. Resident-FBL replacement still requires verified board wiring and a tested recovery path before activation.

FCD/ZGW changes belong to their respective repositories and require their own source/test/target validation. The exact G26-local protocol is in [PROGRAMMING_PROTOCOL](../bootloader/PROGRAMMING_PROTOCOL.md); external changes are itemized in [EXTERNAL_INTEGRATION_DEPENDENCIES](../compatibility/EXTERNAL_INTEGRATION_DEPENDENCIES.md).

## Evidence and readiness

`Modernization/tests/run_tests.py` exercises the portable resident FBL, BSW/DEM/Fee journal, CAN/ISO-TP/DCM, SRAM updater and UART paths. It includes negative cases for missing resident-FBL NRC78 confirmation and failed APP DCM NRC78 confirmation. `Modernization/tools/build_firmware.py` compiles the actual APP/FBL project selections and checks flash-busy helpers and FBL SRAM closure. The `legacy` and `can` APP/FBL builds, updater-enabled FBL build, and native suites passed on 2026-10-24 after the DID addition. The linked CAN APP uses 53,565 of 261,632 flash bytes; the CAN resident FBL uses 17,620 of 65,536 flash bytes. These are build and host results, not physical measurements. No board, CAN bus, power-interruption or FCD/ZGW/G26 programming session was exercised in this audit.

The G26 APP/FBL are substantially implemented for their configured lab subset, but they are **not complete** against unrestricted AUTOSAR, UDS or ISO-TP configurations and are **not ready to flash** on the current evidence. Source integration is configured; target gateway build, board wiring, end-to-end transport, power-interruption recovery and feature regression remain required.
