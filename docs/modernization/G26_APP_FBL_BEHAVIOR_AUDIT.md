# G26 APP/FBL behavior audit — 2026-10-24

The target is a connected AUTOSAR Classic-like laboratory implementation without RTE, not formal AUTOSAR certification or support for every standardized service. This assessment follows the active APP/FBL source, the ZGW reference and the current RepoCM5 FCD source. Source behavior, host tests, Cortex-M linking, gateway integration and physical ECU behavior are separate evidence levels.

## FCD and ZGW contract

The G26 APP-image programming wire sequence is `10 02`, `31 01 00 01` with vector address and size, `34 00 44` with the same range, `36` blocks of at most 240 data bytes, and `37` with a big-endian IEEE CRC32. The FBL creates the 512-byte header, so the transferred image begins at `0x08020200`. This can be represented by a G26-specific FCD profile, but none is currently configured.

Current RepoCM5 `Diagnostics/FCD/FCD.pyw` does not list G26 in `DEFAULT_EXTENDED_DIAG_ADDRESSES`; its generic FBL-image branch sends RID `0200` before RID `0155`, then erase. G26's resident FBL has no RID `0200` and intentionally rejects RID `0155` while the updater interlock is off. The ZGW G26 return route for response ID `0x709`, target address `0x55` and gateway flow-control address `0x41` is also unproved. Thus the current FCD workflow is **not end-to-end compatible with G26**, especially for resident FBL replacement. Adding a profile or accepting the generic RID would not make physical updating safe or proved.

FCD/ZGW changes belong to their respective repositories and require their own source/test/target validation. The exact G26-local protocol is in [PROGRAMMING_PROTOCOL](../bootloader/PROGRAMMING_PROTOCOL.md); external changes are itemized in [EXTERNAL_INTEGRATION_DEPENDENCIES](../compatibility/EXTERNAL_INTEGRATION_DEPENDENCIES.md).

## Evidence and readiness

`Modernization/tests/run_tests.py` exercises the portable resident FBL, BSW/DEM/Fee journal, CAN/ISO-TP/DCM, SRAM updater and UART paths. It includes negative cases for missing resident-FBL NRC78 confirmation and failed APP DCM NRC78 confirmation. `Modernization/tools/build_firmware.py` compiles the actual APP/FBL project selections and checks flash-busy helpers and FBL SRAM closure. The `legacy` and `can` APP/FBL builds, updater-enabled FBL build, native suites, source integration gates and negative SRAM closure test passed on 2026-10-24. The linked CAN APP uses 53,565 of 261,632 flash bytes; the CAN resident FBL uses 17,104 of 65,536 flash bytes. These are build and host results, not physical measurements. No board, CAN bus, power-interruption or FCD/ZGW/G26 programming session was exercised in this audit.

The G26 APP/FBL are substantially implemented for their configured lab subset, but they are **not complete** against unrestricted AUTOSAR, UDS or ISO-TP configurations and are **not ready to flash** on the current evidence. The named hardware and external integration gaps above are prerequisites, not source-only test failures.
